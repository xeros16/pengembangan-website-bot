INSTALLATION
1. Stop the running website and create a full backup of the project, MongoDB database, uploads and WhatsApp session folders.
2. Extract Part 1 into the project root and choose Merge/Replace.
3. Extract Part 2 into the same project root and choose Merge/Replace.
4. Preserve local .env files, portfolio-website/models.js, database data, uploads/media and WhatsApp auth/session folders.
5. Keep TRUST_CLOUDFLARE_IP_HEADER=false unless the origin is firewalled to accept traffic only from Cloudflare.
6. Start the bot and website using the existing deployment procedure.
7. Hard-refresh the website with Ctrl + Shift + R.

WHAT CHANGED
- WhatsApp setup/activation tokens are now consumed with an expiry-aware atomic compare-and-set update.
- Concurrent activation attempts cannot both activate the same setup token.
- A duplicate email race is handled as HTTP 409 instead of surfacing as a generic server error.
- Designer Studio login now consumes WhatsApp OTP atomically before issuing a session; one OTP cannot create multiple concurrent sessions.
- Failed OTP attempts increment only the same active OTP and stop at the configured limit.
- Password changes are throttled and compare-and-set against the current password hash to prevent concurrent overwrites.
- Password setup, password change and password reset invalidate previously issued WhatsApp OTPs.
- Existing IP/identity throttles, email verification confirmation, CSRF, session hashing, cookie parsing and HTTP hardening from v5.85 remain intact.
- Root JavaScript syntax checks now include the website source and tests while excluding node_modules and .git.

PRESERVED
- No MongoDB schema migration or new runtime dependency is required.
- Existing profile, portfolio, client project, Designer Studio and WhatsApp bot features remain in place.
- Existing design system, themes, responsive navigation, GSAP and reduced-motion behavior remain in place.
- Local .env, database contents, uploads, media and WhatsApp authentication sessions must not be replaced.
